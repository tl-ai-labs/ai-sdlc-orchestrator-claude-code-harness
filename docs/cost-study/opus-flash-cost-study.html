Cost study · public profile page, ~15 files · 16–25 Sep 2026

Where the Opus + Flash money actually goes

Eighteen changes, measured on the same task each time — about 32 complete runs over ten days. The headline is not what anyone expected: most of the saving came from cutting Opus overhead, which helped both setups. On the newest plugin versions Opus + Flash is now about 20% cheaper.

The task

What every run built

Each run below did the same task on the Kaneo codebase, started with this command in Claude Code:

/mmo:brownfield "add a new public profile page with default profile image"
Where it stands · 25 Sep

Opus + Flash won all three newest pairs

We ran three same-version pairs on the two newest plugin versions. On the full bill, Opus + Flash was cheaper every time: $9.79 vs $13.98 (0.8.8), $9.36 vs $9.55 (0.8.9, a tie), and $8.37 vs $11.28 (0.8.9 again). Averaged, Opus + Flash cost $9.17 a run against $11.60 for Opus-only — about 21% less. Counting only the work itself (leaving out chat that landed in the same time window), it is $8.14 vs $10.07, about 19% less; there Opus-only won the middle pair by a small margin.

The core discovery

Flash is not the expensive part. Opus is.

Across every run, Flash cost between $0.05 and $0.66. Over 90 percent of the bill is Opus thinking, reading and planning. In one run the total came to $22.55 while Flash's share was $2.39.

That reframes the problem. The question is not how to make Flash cheaper. It is how to stop Opus spending so much preparing work for Flash and cleaning up afterwards.

Plugin 0.7.3 · 16–17 Sep

Starting point

What we implemented

  • Opus plans and reviews; the coding is handed to a cheaper model (Flash, or Sonnet as a trial).

Runs and results

What happened

Flash cost only $0.12, yet the Flash setup was 36% dearer than Opus alone. The planner wrote the whole program into the plan (1,011 lines, 62 code blocks), Flash copied it word for word, and Opus then re-typed and re-read Flash's files.

  • Flash itself was almost free.

Defects

Advantages and defects

What each setup is good and bad at

Opus-only — advantages

  • Cheapest Opus-only run: $9.55 in Row 18 (about $7.37 for the run itself).
  • Simple: one model, no hand-offs, nothing to translate between models.
  • Often gets every task right first time (15 / 15, 12 / 12, 11 / 11).
  • Needs no second AI provider or extra API key.

Opus-only — defects

  • Does every task one after another, so it cannot work in parallel.
  • Big swings on identical runs: $14.86 and $17.40 on the same setup.
  • Sensitive to memory timing: a 5-minute memory run cost $17.43 because long test waits made it reload.
  • Swings a lot between runs: $13.98 in Rows 16–17, then $9.55 and $11.28 in Row 18.

Opus + Flash — advantages

  • Flash is extremely cheap: $0.05–$0.66 a run, under $0.10 in the latest runs.
  • Flash writes all the code in one parallel batch — 19 of 19 tasks in 47 seconds.
  • Its last three runs cost $9.79, $9.36 and $8.37 — the three cheapest Flash runs. Won in Rows 1–3, 8, 10, 16–17 and 18.
  • Same quality: all tests passed, zero serious review issues.

Opus + Flash — defects

  • Opus spends more preparing work: a code scan and a longer plan (766 vs 407 lines).
  • When the task splitter misread the plan, Opus fixed it by hand, which cost extra.
  • Earlier versions needed many retries; since Row 14 almost none (19 / 19 right first try in Row 18).
  • More parts that can break: a setup bug once cost about $1.10 per run, and a manager pausing to wait cost $4.10 in Row 15.
  • Depends on a second provider: Google's Flash service was too busy 8 times in Row 18.

Every comparison rests on one to three runs per setup. Identical runs differ by up to $2.50, so a single gap under that means little. Over the three newest pairs Opus + Flash was cheaper on the full bill every time, by $4.19, $0.19 and $2.91.

Reading the numbers

What we learned

  • On the newest versions Opus + Flash is cheaper.It won all three newest pairs on the full bill ($9.17 vs $11.60 on average, about 21% less). One of the three was a near tie.
  • Both setups became far cheaper.Opus + Flash fell from $26.02 to $8.37, down 68%. Opus-only fell from $19.16 to $9.55 at its best, down 50%.
  • The biggest single saving was the manager not stopping to wait.Each pause cost a full reload of Opus's memory. Three pauses cost about $4.10 in one run, more than Flash has cost across the whole study.
  • Most of the saving came from removing waste, not from delegation.The changes that paid best helped both setups equally.
  • Flash's own cost is not the main factor.It ranged from $0.05 to $0.66 a run, while over 90% of the bill is Opus thinking, reading and planning.
  • Removing Opus overhead helped both setups.Exact imports and the import checker made Flash reliable, but leaner reviewers and no pauses cut Opus-only's cost just as much.
  • A gap under $2 means nothing on its own.Identical runs vary by around $2.50. Over every run since 23 Sep the setups are even ($12.08 vs $12.14); the gap only opened after the 0.8.8 fixes.
  • Quality held throughout.All tests passed in every run, and the latest runs had zero serious review issues.

Sources and tools

Where these numbers come from

Tools used

  • Claude Code running the mmo plugin (versions 0.7.3 → 0.8.9), started with /mmo:brownfield.
  • Claude Opus 5 for planning, reviews and (in Opus-only) all coding; Gemini Flash for coding in the Opus + Flash setup.
  • model-dispatch server (part of the plugin) that sends work to Flash, checks it and retries.
  • Kaneo's own checks: pnpm test (Vitest), TypeScript type checks and the Biome formatter.
  • One Windows laptop running Linux (WSL) for every run, so the machine is the same throughout.

Where the figures are recorded

  • Cost per run: the plugin's usage collector (collect-orchestrator-usage.mjs), which prices every Claude message at public list prices from the Claude Code session logs.
  • Per-run records: .sdlc/runs/<run-id>/ in the Kaneo repo — the brief (intent_brief.md), plan, test results, reviews, notes.md, telemetry.jsonl and the code change as change.patch.
  • Summaries: .sdlc/ledger.md (one row per run) and .sdlc/policy-study.md (comparison and read-outs).
  • The list of changes and savings targets: docs/planning/opus-plus-flash-cost-plan.md in the plugin repo.
